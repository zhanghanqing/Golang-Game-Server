# idgen —— 雪花 ID

[English](README.md)

无需中心数据库即可生成全局唯一、大致按时间递增的 63 位整数 —— 用于玩家 uid
（也适合道具实例、邮件、订单、公会等）。

```
 63        62                       22            12             0
 ┌─────────┬────────────────────────┬─────────────┬──────────────┐
 │ 0 (符号)│ 41 位：距 Epoch 的毫秒数 │ 10 位       │ 12 位        │
 │         │（约 69 年）              │ worker id   │ 序列号        │
 └─────────┴────────────────────────┴─────────────┴──────────────┘
 Epoch = 2024-01-01 UTC   1024 个 worker   每 worker 每毫秒 4096 个
```

```go
g, _ := idgen.NewSnowflake(cfg.Node.WorkerID) // 0..1023，每个进程唯一
uid := g.Next()
t, worker, seq := idgen.Parse(uid)            // 调试用
```

| 情况 | 行为 |
|---|---|
| 1 毫秒内超过 4096 个 | 借用下一毫秒（逻辑时钟），不阻塞、不重复 |
| 时钟回拨（NTP 校时） | 继续使用上一次的时间戳；ID 依然唯一且递增 |
| 两个进程使用相同 worker id | **可能重复** —— 每个进程必须分配不同的 `worker_id`（配置或环境变量 `WORKER_ID`） |

为什么不用 UUID？64 位整数在 protobuf 中更紧凑（varint）、数据库索引友好、按创建时间有序、日志里也好读。
